# QuickCal-Calendar

这是 QuickCal 移动端日历桥接的唯一母版规范。网页必须收到与本次任务匹配的写入回执，才可以显示成功。

## 现有快捷指令

- 快捷指令名称必须固定为 `QuickCal-Calendar`。
- 现有快捷指令必须升级到协议 v2；旧版没有写入回执，网页会正确显示“未确认写入”，不会再假报成功。
- 日历目标不得写死为某个开发者账号中的“工作”日历；导入时必须让每位用户选择自己可见、可写的目标日历。

## 输入协议

快捷指令输入是一段 JSON 文本：

```json
{
  "version": 2,
  "eventId": "bridge-...",
  "receipt": "created:bridge-...",
  "verificationToken": "QuickCal-ID:bridge-...",
  "title": "QuickCal 桥接测试",
  "start": "2026-09-24T15:00:00+08:00",
  "end": "2026-09-24T15:30:00+08:00",
  "allDay": false
}
```

## 动作顺序

1. “从输入获取字典”，输入为“快捷指令输入”。
2. 分别获取 `title`、`start`、`end`、`allDay`、`eventId`、`receipt` 和 `verificationToken`。
3. 将 `start` 和 `end` 转换为日期。它们必须保留 ISO 8601 中的时区偏移。
4. 使用“添加新日程”：
   - 标题：`title`
   - 开始：转换后的 `start`
   - 结束：转换后的 `end`
   - 日历：在导入问题中让用户选择一次目标日历
   - 备注：`verificationToken`
   - “显示编写表单”：关闭
5. 紧接着使用“停止并输出”，输出输入中的 `receipt`。只有“添加新日程”动作成功结束，快捷指令才会走到这一步；若日历权限被拒绝或动作报错，系统会走 `x-error`，不会产生成功回执。

网页的 `x-success` 回调会把“停止并输出”的文本放在 `result` 参数中。网页还会核对它是否严格等于本次请求的 `created:<eventId>`；缺失、空值或属于另一条任务的回执都视为未写入。

不要在快捷指令中额外打开 QuickCal URL；返回由调用方的 `x-success`、`x-cancel`、`x-error` 统一控制。

## 分享前验收

- 安装预览能看到全部动作，不是空白。
- 导入时只需要选择一次目标日历，不需要输入名称。
- 首次运行只出现 Apple 的日历权限询问。
- 创建的标题、开始时间、结束时间准确，且目标日历在系统日历 App 中处于可见状态。
- 不出现日历编辑表单。
- 完成后自动返回测试页。
- 只有“添加新日程”动作完成且回传本次任务的唯一回执时，网页才显示“已确认加入 Apple 日历”。
- 删除“停止并输出”或让它输出空值后测试，网页必须拒绝显示成功，并引导安装最新版。
- 取消、报错和不匹配的旧回执都不会显示成功，也不会把任务保存到 QuickCal。
